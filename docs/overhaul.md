# Lighttime overhaul and migration

The 2026-10-23 overhaul replaces the implementation previously at
[`00748ac`](https://github.com/aaditagrawal/zhiyun-light-control/commit/00748ac38d24f86cc1d4a02b4ad135f503f16889).
The repository keeps its **Zhiyun Light Control** name and Git history;
**Lighttime** names the replacement SDK and tools. This is a source/API
replacement, without a compatibility shim.

## What changed

The earlier README described a GPT‑5.5 xHigh / Codex reverse-engineering
experiment. The overhaul used **GPT‑6.1 Sol in T3 Code through Codex**, with
parallel protocol research, implementation and review. The user supplied device
access and requested Python, TypeScript, browser, OBS and Android support.
The workflow is recorded alongside concrete implementation and validation
results.

- Verified Linux BLE control replaces the former experimental output-control
  path. Setters wait for BLE write acknowledgement, then query and verify actual
  brightness/CCT; the G60 does not send a protocol setter reply.
- A local HTTP/SSE bridge lets multiple clients share one BLE owner, with
  optional authentication. It includes asynchronous Python and TypeScript
  clients and a browser UI. The default command now discovers/connects one
  nearby G60 and opens controls without address or token setup.
- OBS gains a worker-based script and browser-dock setup. Expo Android gains
  a direct BLE app and a compiled, inspected arm64 preview APK.
- Shared effects are generated by the bridge using brightness/CCT commands;
  [the effect contract](effects-contract.md) defines timing, stop/restore and
  interaction with manual controls. They do not use unverified firmware effects.
- Subsequent isolated USB probes established brightness/CCT writes using the
  ordinary `00 01` address pair. Bluetooth readback verified 60 repeated cases.
  Pure USB state reads remain unanswered; echoed frames are not verification.

## Moving an existing integration

1. Use Python 3.13+ and `uv run --frozen lighttime` in this checkout. `uv run`
   prepares the environment; a separate sync step is unnecessary. The previous Python
   3.10 minimum and optional `[ble]` / `[dev]` extras no longer apply; development
   tooling uses the locked `dev` dependency group. The package is not on PyPI.
2. Replace imports from `zhiyun_light_control` with a rewritten integration
   using `lighttime.LightClient` or `lighttime.BridgeClient`. The direct SDK is
   asynchronous; old synchronous clients and connection-config APIs are gone.
   See [Python examples](python.md).
3. Replace `zlight` commands with `lighttime scan`, `state`, `set`, `serve` or
   `usb-info`; no arguments now means `serve`. Flags, output shapes and HTTP
   endpoints have changed; consult `uv run --frozen lighttime --help` and
   [the v1 contract](api-contract.md).
4. Replace experimental USB output writes with direct BLE or the shared bridge.
   Release existing controller connections first. The default loopback bridge
   is tokenless; `--auth` opts into bearer authentication, with optional
   `--token-file PATH`. Existing `--no-auth` commands remain compatible.
   Addressless connect reuses the existing connection or discovers a single
   PL103; several candidates require explicit selection. Allow exact origins
   when a browser UI is served separately. See [website integration](integrating-sites.md).
5. Use whole-percent brightness and 100 K CCT steps. Fractional/intermediate
   inputs are rejected before writing. Reconnecting starts a new controller
   lifetime and can reset the remembered on/restore brightness to 5%.
6. For TypeScript, build the local `@lighttime/sdk` package; it is not on npm.
   For Android, build or install a native APK, rather than Expo Go. See
   [TypeScript](typescript.md) and [Android](android.md).

## Removed functionality

The old OSC, Art-Net and sACN servers are **removed**. Named multi-fixture
rigs, rig/project JSON files, plans, cues, transitions, setup profiles,
registration/provisioning commands and the old scene/preset controller APIs
are **not retained**. There is no old-format configuration importer. Existing
show integrations must be rewritten around the new single-light bridge or
remain on a prior Git revision. OBS program-scene presets and the new shared
effects have their own documented interfaces; they do not make old rig/plan
files compatible.

## Evidence and release limits

[The validation record](validation.md) distinguishes physical G60 results from
offline tests. Linux BLE output, bridge clients, the browser controller and
the OBS HTTP worker were exercised with hardware. USB output was subsequently
verified through Bluetooth readback. Pure USB state reads, direct browser
Bluetooth, Windows/macOS hardware and an installed OBS UI remain unverified.
The Android APK embeds Hermes and uses a public debug/test signing key;
physical startup, permissions and BLE checks await a connected phone. The
known high-severity Expo CLI dependency advisory remains documented in
[Android notes](android.md).

CI runs frozen Python 3.13/3.14 tests, Ruff and ty, Bun SDK tests/build/types,
and Android offline tests/types. It does not build native Android, use EAS,
run vendor apps, access hardware or publish packages.
