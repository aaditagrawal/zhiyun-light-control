# Shared effect contract

Effects are generated by the bridge from the G60's verified brightness/CCT
commands. They are not unverified vendor firmware effect commands. One bridge
runs one effect at a time, independently of the browser that started it.

Default authenticated endpoints, with the same origin/token policy as device
control (the explicit personal no-auth mode is specified below):

- `GET /v1/effects`: current `EffectStatus`.
- `POST /v1/effects/start`: an `EffectConfig`; returns `EffectStatus` after
  accepting the task and capturing verified baseline state.
- `POST /v1/effects/stop`: `{ "restore"?: boolean }`, default `true`;
  returns `EffectStatus` after cancelling and, when requested, verifying the
  original brightness/CCT restoration. No active effect is an idempotent stop.

`EffectConfig` has required `pattern`: `blink`, `breathe`, `fade-in`, `fade-out`
or `cct-sweep`. Optional fields:

| Field | Meaning / default |
| --- | --- |
| `duration` | Seconds, 1–3600; default 10. `null` means until stopped for cyclic patterns only. |
| `period` | Cycle length, 1–60 seconds; default 4. Fades use duration. |
| `minBrightness` | Whole percent 0–100, default 0. |
| `maxBrightness` | Whole percent 0–100, default verified nonzero baseline or 5. Must be >= min. |
| `cct` | 2700–6500 K in 100 K steps; default baseline CCT. |
| `cctEnd` | Same range/resolution, default 6500; sweep interpolates cct to cctEnd. |
| `restoreOnComplete` | Boolean; default true for cyclic patterns, false for fades. |

Reject unknown fields and invalid/non-finite inputs before any output write.
Blink alternates max/min. Breathe follows a smooth rise/fall curve. Fade-in
interpolates min to max; fade-out max to min. CCT sweep goes out and back while
holding max brightness. A finite fade holds its exact endpoint unless restore
was requested. Brightness/CCT are quantized to actual hardware resolution.

`EffectStatus` is:

```ts
{
  running: boolean;
  id: string | null;
  pattern: 'blink' | 'breathe' | 'fade-in' | 'fade-out' | 'cct-sweep' | null;
  startedAt: string | null;
  endsAt: string | null;
  progress: number | null; // 0..1 for a finite run; null for idle/unbounded
  lastError: string | null;
}
```

Hardware output updates are serialized with manual writes, use monotonic
timing, skip identical quantized targets, run at most five updates per second,
and verify actual readback. A late frame must never replay after cancellation.
Manual state writes stop the effect without restoration before applying the
manual setting. Explicit disconnect stops the effect; no effect survives a
device replacement. Shutdown cancels/drains effect work before client cleanup
and does not start restoration writes while stopping. Errors stop the runner
and remain visible through lastError; stale values are never called verified.
Normal state SSE continues to report actual output. Effect status is a separate
query; clients may poll it once per second while attached.

Python `BridgeClient`: `effect()`, `start_effect(pattern, **options)`,
`stop_effect(restore=True)`. TypeScript `BridgeClient`: `effect(options?)`,
`startEffect(config, options?)`, `stopEffect({restore?}, options?)`.
TypeScript exports `EffectPattern`, `EffectConfig`, and `EffectStatus`.

## Personal local mode and health metadata

For this personal testing site, the runtime may explicitly use `--no-auth`
(`Bridge(auth_required=False)`). Effects/state/connect/SSE then accept requests
without bearer tokens; the existing same-origin/exact allowlist policy still
applies. Default bridges remain authenticated. Clients may omit a token, and
must omit the Authorization header when the token is absent or empty.

`GET /v1/health` always returns `{ "name": "lighttime", "version": "0.1.0",
"authRequired": boolean }`. When `authRequired` is false it additionally
returns `"defaultAddress": string | null`, using the configured startup BLE
address (null when none). Authenticated health omits `defaultAddress`.
The personal UI opens directly to controls and uses health metadata to
reconnect; it does not require tokens, connectors or a setup flow. The parent
owns loopback binding, Tailscale Serve HTTPS and the exact HTTPS origin allowlist.
